# Test Creation Artifacts

This folder holds the structured artifacts produced by **Module 2** (Test Creation). These are the intermediate and output files between business-level comprehension and executable Playwright test specs. All files here are written by the pipeline — do not edit them manually.

---

## File inventory

### `test_suite.json`

The single source of truth for every generated spec and its status. Updated after each pipeline run and after any healing pass.

```json
{
  "project": "YourProjectName",
  "updated_at": "2026-06-01T10:00:00Z",
  "total_scenarios": 10,
  "new_additions": ["test_SC-M01-001_login.spec.ts"],
  "specs": [
    {
      "spec_id": "SC-M01-001",
      "scenario_title": "Successful Login",
      "module_id": "M01",
      "file": "M01/test_SC-M01-001_login.spec.ts",
      "status": "new",
      "tier_used": 0,
      "fallback_route": null,
      "generated_at": "2026-06-01T10:00:00Z",
      "last_run": null,
      "last_result": null
    }
  ]
}
```

| `status` | Meaning |
|----------|---------|
| `new` | Generated by primary LLM — not yet run |
| `degraded_fallback` | Generated by Python fallback — needs review |
| `healed` | Fixed by HealingAgent via LLM |
| `healed_fallback` | Fixed by CSS-based fallback |

`tier_used`: `0` = primary LLM, `1` = NSHTTPConnector, `2` = Python fallback.

### `scenario_element_map.json`

Maps each business scenario to the 3-7 DOM elements relevant to its steps. Produced by SemanticMapAgent in a single LLM call before script generation — prevents sending all 60+ DOM elements per scenario prompt.

```json
{
  "SC-M01-001": {
    "scenario_title": "Successful Login",
    "relevant_elements": [
      {
        "locator_id": "LOC-0003",
        "playwright_expr": "page.getByPlaceholder('Username')",
        "relevance": "primary username input — used in step 1"
      },
      {
        "locator_id": "LOC-0004",
        "playwright_expr": "page.getByPlaceholder('Password')",
        "relevance": "password input — used in step 2"
      }
    ]
  }
}
```

## `test_scripts/` subdirectory structure

Scripts are organized into subdirectories by execution level:

```
test_scripts/
├── individual/               ← one .spec.ts per scenario (Level 1 — single test)
│   ├── test_SC-M01-001_login.spec.ts
│   └── test_SC-M02-001_dashboard_load.spec.ts
│
├── M01/                      ← all M01 specs grouped (Level 2 — run whole module)
│   └── test_SC-M01-001_login.spec.ts
│
├── M02/                      ← all M02 specs grouped
│   └── test_SC-M02-001_dashboard_load.spec.ts
│
└── workflows/                ← cross-module workflow specs (Level 4 — e.g. login → dashboard → checkout)
    └── complete_flow.spec.ts
```

Level 3 (suite) execution reads from `individual/` using the scenario IDs listed in `test_suites/*.json`.

## Deprecated (removed in this architecture)

The following files from the previous architecture are no longer produced:

| Removed | Replaced by |
|---------|-------------|
| `intents.yaml` | `scenario_element_map.json` + `comprehension/dom_intents.json` |

| `test_suite.yaml` | `test_suite.json` (JSON only) |
| `locators.json` | Eliminated — Playwright expressions come directly from `dom_elements.json` |
